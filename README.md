# T-Py-T Homebrew Tap

**`brew tap T-Py-T/tap`, and two tools are one command away.**

A public [Homebrew tap](https://docs.brew.sh/How-to-Create-and-Maintain-a-Tap)
with a formula for the `atomic` coding-agent runtime and a Cask for
`mac-ogcs`, a terminal Outlook-to-Google Calendar sync. Every definition,
checksum and template is readable here, and every pull request goes through
`brew test-bot`.

## Getting started

### Prerequisites

- [Homebrew](https://brew.sh/)
- macOS for `mac-ogcs` (the Cask declares `depends_on :macos`)

### Tap and look around

```sh
brew tap T-Py-T/tap
brew info T-Py-T/tap/atomic
brew info --cask T-Py-T/tap/mac-ogcs
```

`brew info` shows the version, description, homepage and requirements without
downloading anything. On the current `main`:

```text
==> t-py-t/tap/atomic: stable 0.9.13
Verifiable coding agent runtime
https://github.com/bastani-inc/atomic

==> mac-ogcs (mac-ogcs): 0.2.2
Privacy-first Outlook-to-Google Calendar sync for terminals
https://github.com/T-Py-T/mac-ogcs
```

### Install atomic

```sh
brew install T-Py-T/tap/atomic
atomic --help
```

Upgrade with `brew upgrade T-Py-T/tap/atomic`. On macOS the formula also
rewrites the library paths of atomic's embedded PostgreSQL binaries so they
load from inside the install, rather than from `/Library/PostgreSQL/18/lib/`.

## Install mac-ogcs (private release)

The Cask is public, but the release archive it downloads lives in the private
`T-Py-T/mac-ogcs` repository. Homebrew can only fetch it with a GitHub token
that has read access to that repository.

1. **Get your own token.** Use a GitHub token you already have, or create a
   fine-grained personal access token limited to `T-Py-T/mac-ogcs` with
   read-only **Contents** access. Keep it in your password manager or system
   credential store.
2. **Export it for this shell only**, without leaving it in your shell
   history. For example, paste it at a silent prompt:

   ```sh
   read -rs HOMEBREW_GITHUB_API_TOKEN && export HOMEBREW_GITHUB_API_TOKEN
   ```

   Loading it straight from your credential store's CLI works too.
3. **Install, then clear it:**

   ```sh
   brew install --cask T-Py-T/tap/mac-ogcs
   unset HOMEBREW_GITHUB_API_TOKEN
   ```

Repeat steps 2–3 for `brew upgrade --cask T-Py-T/tap/mac-ogcs`. The token is
read only at download time by the strategy in [`lib/`](lib). It is never
written into the Cask. Without it, the download fails with
`HOMEBREW_GITHUB_API_TOKEN is required`.

After installing, run `mac-ogcs`. The Cask's caveats list its keys: `n` to
sync now, `r` for a recurring schedule, `g` for Google calendar settings. The
Cask also states that the binary is Developer ID signed and notarized. It
keeps normal quarantine metadata and has no Gatekeeper bypass hook.

## Focus Owned preparation

[`Templates/focus-owned.rb.tmpl`](Templates/focus-owned.rb.tmpl) prepares an Apple-silicon app and CLI package using private release downloads. It is not installable until a qualified release and checksum exist. See the [release and update handoff](docs/FOCUS_OWNED.md).

## How it's built

```text
Formula/    source- or bottle-style packages (atomic from npm)
Casks/      prebuilt binaries and apps (mac-ogcs, generated by GoReleaser)
lib/        Ruby download strategy for private GitHub release assets
Templates/  non-installable starting points for new packages
.github/    pull-request-only brew test-bot workflow
```

`mac-ogcs` is a terminal tool, but it ships as a Cask. A Cask `binary`
artifact links a prebuilt executable without a desktop `.app` or a compiler
on the target Mac. The private-release strategy is a separate class in `lib/`
that the Cask loads. That keeps the Cask block clean for Homebrew's style
rules.

## Validate a change

Run Homebrew's tap checks before opening a pull request:

```sh
brew test-bot --only-tap-syntax --tap=T-Py-T/tap
```

This runs `brew style`, `brew readall` for all OSes and architectures, and
`brew audit --tap`. It checks the tap as installed under Homebrew's `Taps`
directory. The pull-request workflow runs the same gate on the PR's exact
commit. It doesn't run on pushes, schedules or manual dispatches.

## Add or update a package

1. Publish signed release archives for Apple silicon and Intel.
2. Calculate the SHA-256 checksum of each final archive.
3. Copy the right template from `Templates/` into `Casks/` or `Formula/` and
   replace every placeholder.
4. Run `brew style` and `brew audit --strict` for the new package.
5. Open a pull request and wait for the tap checks to pass before merging.

Don't add quarantine-removal hooks. Release artifacts must pass normal macOS
Gatekeeper checks.
